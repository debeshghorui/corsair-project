# Auth provider sits behind an app-owned session seam

The app talks to a session (who is signed in, sign out, sign-in screen, request protection) and Clerk is only the current adapter for that seam. Callers never import the provider SDK. Replacing Clerk means swapping the adapter under `src/server/auth/adapters/clerk` and `src/components/auth/clerk`, plus the request gate in `src/proxy.ts`. Next.js has to see `clerkMiddleware` and its matcher written in that proxy file, so the route list lives in `public-routes.ts` and the proxy is the one place that still calls the provider's middleware directly. A provider-agnostic session type was chosen over calling Clerk from each page, because the product already treats the signed-in person as a tenant and that identity should not change when the login vendor does.
